# 持续执行与完成检查

开发分支：`codex/persist-agent-until-complete`，基于 `pr-19@f4dcf1e`。

## 当前行为

- 普通流式、Agent 流式（含临时聊天）及非流式 Chat 共用完成监督逻辑。有效工具轮次不再限制为 20 次。
- 模型返回 `stop` 后，独立的 JSON 完成检查根据原始请求、追加约束、工具结果及候选答案，决定完成、继续、缺少输入或外部受阻。未完成就将下一步放回同一执行上下文，继续循环。
- `length` 或不完整结束不能直接表示任务完成；长正文有新内容时可继续分段输出，截断的工具参数不会执行。
- 任务执行前的模型请求遇到网络异常、408、429、5xx，最多自动重试 3 次。该机制不重放工具调用。
- 每次新的工具调用参数/结果组合会重置无进展计数。重复结果达到 3 次时提示更换策略，连续 6 次重复结果时明确报告未完成；连续 4 次拟结束/检查失败且没有新进展时也明确中断，避免空转。
- 完成检查要求具体证据；失效或格式错误的检查结果不会被当作成功。必要信息缺失或确实外部受阻时，报告具体原因。
- 原有运行后反思保留评分及建议，但不再从原始请求重新执行一遍任务。必要的续做发生在保留工具证据的执行循环内。
- 用户取消向下传播到工具，Shell 子进程树随之终止。原有手动确认流程保留。

## Shell

`run_shell` 默认超时由 30 秒改为 120 秒，可传 `timeout_seconds`（整数，1–3600）调整。
超时返回原因和部分输出，已落盘文件保留；建议长任务分批保存结果，再从文件续跑。
Windows 使用隐藏控制台初始化 UTF-8，再执行用户命令，并设置 Python UTF-8 环境变量。

## 成本与边界

完成检查在每次候选最终回复时增加一次模型请求（包含纯问答），不是在每个正常工具轮次后调用。
检查仍依赖模型判断，不是业务结果正确性的形式证明；实际交付要求和工具证据会影响判断质量。
本次实现为当前 HTTP 请求内的连续执行；没有实现断线/服务重启后的持久后台任务，也没有新增上下文压缩或浏览器专用工具。
模型上下文容量、不可恢复的服务故障、用户取消和真正的外部阻碍仍会终止本次运行。
附件中 HTML 导出白名单等其他建议不属于本次修改。
