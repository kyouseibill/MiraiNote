# REQ-01 用户认证（Auth）

> 版本：v1.0  
> 最后更新：2026-05  
> 状态：待开发

---

## 1. 功能概述

MiraiNote 支持两种账户创建方式（管理员创建 + 用户自行注册），登录方式为**用户名 + 密码**，并通过**邮箱验证**完成注册激活。支持"记住我"长期登录。手机号 / 短信验证码登录预留扩展接口，暂不实现。

---

## 2. 用户故事

- 作为新用户，我希望能自行注册账户，以便开始使用 MiraiNote
- 作为新用户，我希望注册后收到验证邮件，激活后才能正常登录
- 作为管理员，我希望能直接为他人创建账户，无需对方自行注册
- 作为用户，我希望登录时勾选"记住我"，下次打开不用重新登录
- 作为用户，我希望能修改自己的密码
- 作为用户，我希望忘记密码时，能通过邮箱重置密码
- 作为管理员，我希望能禁用某个账户，阻止其登录

---

## 3. 数据模型补充

在 SPEC.md §3.1 `User` 表基础上，补充以下字段：

```
Email               NVARCHAR(200)   NOT NULL UNIQUE   -- 邮箱
IsEmailVerified     BIT             NOT NULL DEFAULT 0 -- 邮箱是否已验证
IsActive            BIT             NOT NULL DEFAULT 1 -- 账户是否启用（管理员可禁用）
LastLoginAt         DATETIME        NULL               -- 最后登录时间
```

新增 `EmailVerifyToken` 表（存储验证码/Token，避免污染 User 表）：

```
Id          INT PK IDENTITY
UserId      INT FK → User.Id
Token       NVARCHAR(200)   NOT NULL   -- 随机生成的 Token（UUID）
Type        NVARCHAR(50)    NOT NULL   -- verify_email / reset_password
ExpiresAt   DATETIME        NOT NULL   -- 过期时间
IsUsed      BIT             NOT NULL DEFAULT 0
-- 公共字段 --
IsDeleted   BIT             NOT NULL DEFAULT 0
CreatedAt   DATETIME        NOT NULL
CreatedBy   INT             NOT NULL DEFAULT 1
UpdatedAt   DATETIME        NOT NULL
UpdatedBy   INT             NOT NULL DEFAULT 1
```

## 4. 功能详细说明

### 4.1 用户自行注册

**流程：**
1. 用户填写注册表单，提交后系统创建账户（`IsEmailVerified = 0`，`IsActive = 1`）
2. 系统发送验证邮件到注册邮箱，邮件包含激活链接（Token 有效期 24 小时）
3. 用户点击邮件中的链接，系统验证 Token，将 `IsEmailVerified` 置为 `1`
4. 验证成功后跳转登录页，提示"邮箱验证成功，请登录"
5. 未验证邮箱的账户**允许登录**，但登录后顶部显示提醒横幅，引导用户完成验证

**注册表单字段：**
- 用户名（必填，4～50个字符，仅允许字母、数字、下划线，不可重复）
- 邮箱（必填，格式校验，不可重复）
- 密码（必填，8～32位，必须包含字母和数字）
- 确认密码（必填，必须与密码一致）

**业务规则：**
- 用户名、邮箱重复时返回明确错误信息（分别提示）
- 同一邮箱 1 小时内最多发送 3 封验证邮件，超限提示"发送过于频繁"
- Token 使用后立即标记 `IsUsed = 1`，不可重复使用
- 过期 Token 点击后提示"链接已过期"，并提供重新发送按钮

---

### 4.2 管理员创建账户

**流程：**
1. 管理员在后台填写新用户信息并提交
2. 系统创建账户，`IsEmailVerified = 1`（管理员创建默认已验证），`IsActive = 1`
3. 系统发送"账户已创建"通知邮件给新用户，邮件中包含初始密码
4. 新用户首次登录后，系统提示修改初始密码（非强制，但有提醒）

**创建表单字段：**
- 用户名（必填）
- 邮箱（必填）
- 初始密码（必填，或由系统自动生成随机密码）
- 是否为管理员（勾选框，默认否）

---

### 4.3 登录

**流程：**
1. 用户输入用户名（或邮箱）+ 密码
2. 校验账户是否存在、密码是否正确、账户是否启用
3. 验证通过后签发 JWT Access Token + Refresh Token
4. 若勾选"记住我"，Refresh Token 有效期为 30 天；否则为 1 天

**登录表单字段：**
- 用户名或邮箱（必填）
- 密码（必填）
- 记住我（勾选框，默认不勾选）

**业务规则：**
- 密码连续错误 5 次，账户锁定 15 分钟，锁定期间返回"账户已暂时锁定"
- 账户被管理员禁用（`IsActive = 0`）时，返回"账户已被禁用，请联系管理员"
- 登录成功后更新 `LastLoginAt`

**Token 规则：**

| Token 类型 | 存储位置 | 有效期（普通） | 有效期（记住我） |
|---|---|---|---|
| Access Token | 内存（Pinia store） | 2 小时 | 2 小时 |
| Refresh Token | HttpOnly Cookie | 1 天 | 30 天 |

- Access Token 过期后，前端自动用 Refresh Token 换取新 Access Token（无感刷新）
- Refresh Token 存储在后端数据库，支持主动吊销（登出时删除）

---

### 4.4 登出

- 前端清除内存中的 Access Token
- 调用后端登出接口，删除数据库中对应的 Refresh Token
- 清除 HttpOnly Cookie
- 跳转至登录页

---

### 4.5 修改密码

**流程：**
1. 用户在个人设置页输入当前密码、新密码、确认新密码
2. 验证当前密码正确后，更新密码哈希
3. 修改成功后，**吊销所有已有 Refresh Token**（强制重新登录）

---

### 4.6 忘记密码 / 重置密码

**流程：**
1. 用户在登录页点击"忘记密码"，输入注册邮箱
2. 系统发送重置密码邮件（Token 有效期 1 小时）
3. 用户点击邮件链接，跳转到重置密码页，输入新密码
4. 重置成功后，**吊销所有已有 Refresh Token**，跳转登录页

**业务规则：**
- 邮箱不存在时，为安全起见，仍显示"已发送，请检查邮箱"（不暴露账户存在与否）
- 同一邮箱 1 小时内最多发送 3 封重置邮件

---

### 4.7 管理员禁用 / 启用账户

- 管理员可在用户列表中禁用（`IsActive = 0`）或启用某账户
- 禁用时同步吊销该账户所有 Refresh Token（立即踢下线）
- 不可禁用超级管理员（`Id = 1`）

## 8. 验收标准

### 注册
- [ ] 填写合法信息后，注册成功，收到验证邮件
- [ ] 用户名重复时，提示"用户名已被使用"
- [ ] 邮箱重复时，提示"邮箱已被注册"
- [ ] 密码不符合规则时，提示具体原因
- [ ] 点击邮件链接后，邮箱验证成功
- [ ] Token 过期后，点击链接提示过期并可重新发送

### 登录
- [ ] 正确账号密码登录成功，跳转首页
- [ ] 错误密码时，提示"用户名或密码错误"
- [ ] 连续错误 5 次后，提示锁定及剩余时间
- [ ] 勾选"记住我"，关闭浏览器重新打开仍保持登录
- [ ] 不勾选"记住我"，1 天后自动退出

### 登出
- [ ] 点击登出后，跳转登录页，刷新页面不自动登录

### 修改密码
- [ ] 当前密码错误时，提示"当前密码不正确"
- [ ] 修改成功后，其他设备自动登出

### 忘记密码
- [ ] 输入已注册邮箱，收到重置邮件
- [ ] 输入未注册邮箱，显示相同的成功提示（不暴露信息）
- [ ] Token 过期后，提示链接失效

### 管理员功能
- [ ] 管理员可创建账户，新用户收到通知邮件
- [ ] 管理员可禁用账户，被禁用用户立即无法使用
- [ ] 不可禁用超级管理员（Id=1）

---

## 9. 安全要求

- 密码使用 BCrypt 哈希存储，不可逆
- 所有 Token（邮箱验证、重置密码）使用 UUID v4 随机生成
- Refresh Token 存储在 HttpOnly Cookie，防止 XSS 窃取
- 重置密码接口对邮箱存在与否统一返回相同响应，防止枚举攻击
- 发送邮件接口加频率限制，防止滥用
