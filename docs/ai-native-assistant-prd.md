## 1. 背景与问题

### 1.1 MiraiNote 的资产

MiraiNote 已经验证了一个个人数据底座的价值：工作记录、生活记录、备忘提醒、AI 周报、长期记忆、可执行 40+ 工具的 Agent、定时任务。这些**数据和 AI 基础设施**是新产品最宝贵的资产。

### 1.2 核心问题：AI 是"附加品"，不是"融合体"

MiraiNote 的形态是典型的 **"一堆功能 + 一个聊天窗口"**：

| 能力 | MiraiNote 现状 | 问题 |
|---|---|---|
| 记录 | 表单式 CRUD 页面 | 录入摩擦大，AI 不在场 |
| AI 对话 | 一级导航的 Chat 页，Agent 模式强大 | 用户要"去 AI 那里"才能用上，AI 与数据割裂 |
| 周报 | 单独页面点"生成" | 生成前的素材积累、生成后的修改都是人工 |
| 记忆 | 后台静默运行 | 用户不可见不可控，信任感弱 |
| 提醒 | 到点弹原文 | 没有上下文，没有"助理感" |

**结论：重建不是加功能，而是换范式** —— 把 AI 从"一个页面"溶解为产品的运行方式本身。

## 2. 产品定位与设计原则

### 2.1 一句话定位

> **Mirai 是一位常驻你电脑里的助理：你随手丢给它一切，它替你记牢、理清、备好，在你需要时带着上下文出现。**

用户心智不是"我在用一个记录软件 + 偶尔问问 AI"，而是"**我有一个助理**"。

### 2.2 四条设计原则（AI-Native 原则）

1. **AI 在场景内，不在场景旁**
   每个界面元素都可被 AI 读取、解释、续写、追问。没有"AI 入口"这种东西——处处都是入口。

2. **输入即处理（Capture → Triage → Dispatch）**
   所有输入先进"捕获收件箱"，由 AI 解析成结构化数据（任务/日程/记录/知识），用户一键确认。用户永远不需要先想清楚"这该建在哪"。

3. **AI 建议，人类签字**
   AI 对用户数据的一切写操作，以**可预览、可撤销的 diff** 呈现，用户确认后落地。AI 自动落地的只有它自己的产出（摘要、标签、记忆），且全部标注来源。

4. **主动服务，数据说话**
   助理不等提问：晨报、到期摘要、周报草稿自动就绪。所有 AI 产出**必须溯源**到具体记录（引用 chips），杜绝编造。

### 2.3 聊天窗口的"溶解"——本设计最关键的决定

传统 Chat 窗口被拆解为三种形态，贯穿全产品：

| 原聊天能力 | 新形态 | 出现位置 |
|---|---|---|
| 万能问答/指令 | **全局指令面板**（⌘K / Ctrl+K） | 任何界面按 Ctrl+K 唤起，自然语言直达任何操作 |
| 针对某内容的讨论 | **上下文侧边对话** | 每条记录/任务/周报右侧展开，自带该对象上下文 |
| 定期汇报/主动告知 | **今日流中的 AI 卡片** + 原生通知 | 晨报、周报草稿、整理建议以卡片推送 |

> ChatSession/ChatMessage 数据结构保留为底层"对话存储"，但不再以一级页面形态存在。原有聊天历史完整迁移，可在指令面板与侧边对话中检索续聊。

## 3. 目标用户与核心场景

**目标用户**：与 MiraiNote 相同——需要同时管理工作与生活的知识工作者/开发者本人（个人单机场景优先）。

**一天的场景剧本**（贯穿全文的主线）：

- **07:30** 开机，托盘弹出晨报卡片："今天 3 件到期事项，其中『给客户回方案』你上周三记录过背景……下午 14:00 有你自设的提醒"
- **09:20** 会议中，全局热键唤起捕获条，语音/一句话丢进去："重构方案要过安全评审，老王周三前要排期，顺便记得给妈买生日礼物"。AI 分拣为 2 条任务（带截止日）+ 1 条工作记录草稿
- **14:00** 写完一段工作记录，选中文字点"提炼"，AI 压缩成两行摘要并打好标签
- **17:30** 任务到期通知，附 AI 摘要的上下文（这条任务的来龙去脉来自哪些记录）
- **周五 16:00** 打开回顾页：周报草稿已就绪，90% 可用，改两句话提交

│  ✦ 收件箱  │   ┌────────────────────────────┐    │  （按需展开）  │

│  ☘ 生活流  │   │ 今天3件事 + 昨日未完 + 一句话  │    │  当前对象的   │
│  ✓ 任务    │   └────────────────────────────┘    │  AI 对话 /   │

导航刻意收敛：**今天 / 收件箱 / 工作流 / 生活流 / 任务 / 周报 / OKR / 记忆 / 设置**。其中周报、OKR、记忆为预留入口——M1 导航先占位（空态页），功能随 M2+ 版本实装，用户的使用路径从第一天就建立。"聊天"不在导航里。

### 4.2 桌面端特有能力（Web 做不到的，必须做满）

| 能力 | 说明 |
|---|---|
| **全局热键捕获** | 任何应用内 `Ctrl+Shift+Space` 唤起悬浮捕获条，不打断当前工作；支持语音输入 |
| **系统托盘常驻** | 开机自启，托盘菜单：今日概览 / 快速捕获 / 暂停提醒 |
| **原生 Toast 通知** | 替代 Web 轮询弹窗；通知带 AI 摘要与两个快捷动作（完成 / 稍后） |
| **离线队列** | 断网时捕获与编辑入本地队列，恢复后同步（V1 允许只读缓存，V2 完整离线） |
| **剪贴板监听（可选，默认关）** | 复制内容时捕获条轻提示"丢给助理？"，用户主动开启 |

## 5. 核心功能设计

> 每个模块统一按【功能描述 / AI 融入点 / 关键交互 / 数据依赖】描述。

### 5.1 今日流（Today）

**功能描述**：打开客户端的默认页，一条按时间组织的信息流，从晨报到此刻，所有该知道的事按序呈现。

**内容构成**：
1. **晨报卡片**（AI，每天首次使用时生成）："今天 N 件到期事项 + 昨日未完成 + 本周进度一句话"。点击任何条目溯源跳转。
2. **到期任务卡**（数据 + AI 摘要）：不止显示任务名，附 AI 从相关记录中提取的上下文摘要与来源引用。
3. **快速捕获条**：常驻信息流顶部。
4. **今日已捕获**：随时间线实时追加你今天的记录/任务动态。
5. **AI 轻建议卡**（克制，每天 ≤2 条）："你这周有 4 条记录提到 X 项目，要为它建一个工作流分组吗？"——建议卡必须带【采纳 / 忽略 / 不再提示】。

**AI 融入点**：晨报生成、任务上下文摘要、建议生成。
**数据依赖**：Task、WorkEntry、ProactiveJob（晨报任务）；沿用 MiraiNote 周报 prompt 的"只用事实、禁止虚构"约束体系。

### 5.2 捕获收件箱（Inbox）★ 全产品核心闭环

**功能描述**：唯一的默认录入入口。任何内容——文字、语音转写、拖入的文件——先进收件箱，AI 解析后给出结构化建议，用户批量确认分发。

**AI 分拣（Triage）**：
- AI 将一条原始输入解析为 N 个候选对象，例如：
  - "重构方案要过安全评审，老王周三前要排期" → 任务【推动安全评审排期 @周三前 关联:重构方案】+ 工作记录草稿【安全评审待排期（老王）】
  - "下周三记得给妈妈买礼物" → 任务【给妈妈买生日礼物 提醒:下周三 09:00】
  - "Go 1.24 的迭代器模式挺有意思" → 知识条目 → 归档或转生活流
- 每条建议以**卡片 diff** 呈现：将创建什么、填了哪些字段、依据什么理解。逐条 ✓/✗，或批量确认。
- 置信度低的内容标注"我不确定，请补充"，不硬猜。

**关键交互**：
```
收件箱列表（按时间）          右侧：分拣预览
┌──────────────────┐   ┌─────────────────────────────┐
│ ● 重构方案要过安…  │ → │ AI 建议创建 2 个对象：          │
│ ○ Go 1.24 迭代器… │   │ ① 任务：推动安全评审排期         │
│ ○ （语音 0:23）    │   │    截止：周三前  优先级：中      │
│                  │   │ ② 工作记录草稿：…（可编辑）      │
│                  │   │ [全部采纳] [逐条确认] [重新分拣]  │
└──────────────────┘   └─────────────────────────────┘
```
- **重新分拣**：用一句话纠正 AI（"第二条不是任务，是想法"），AI 重出方案——纠错本身就是训练数据。
- 未处理条目 >3 天，晨报提醒整理。

**AI 融入点**：解析（实体/时间/意图抽取）、目标归类、字段预填、纠错重分拣。
**数据依赖**：新增 `InboxItem`（raw、AI 解析结果 JSON、status）；分发复用现有各实体 CRUD（即现有 40+ Agent 工具中的 create_* 系列）。

### 5.3 工作流（Work Stream）

**功能描述**：WorkLog 升级为"项目分组的记录流"。左侧项目/标签树，右侧时间线流式记录，每条 Markdown。

**AI 融入点**：
1. **写后提炼**：保存记录后，流内以灰色小字显示 AI 摘要与自动标签（标注"AI"，可点改）。该摘要同时是周报素材——周报质量从录入那一刻开始积累。
2. **续写与润色**：编辑器内选中文字 → 浮动条【提炼 / 展开 / 改语气 / 追问】。"追问"打开侧边对话，上下文即该条记录。
3. **关联提示**：AI 发现与历史记录相关时，摘要下方出现"关联：上周三的方案评审记录"（点击跳转）。
4. **周报进度条**：项目视图顶部常驻"本周素材 12 条 · 覆盖度 ████░"，让周报素材积累可视化。

**数据依赖**：WorkLog → `WorkEntry`（+AiSummary、AutoTags、ProjectId 正规化）。

### 5.4 生活流（Life Stream）

**功能描述**：LifeLog 升级：支持多图、心情从自由文本改为**心情标签 + 强度（1-5）**。

**AI 融入点**：
1. **一句话成文**：输入"今天带豆豆去打疫苗了，他好勇敢"，AI 建议扩写为一条生活记录（用户可改）。
2. **共情回应（可选开关）**：生活流保存后，AI 给一句不超过 30 字的回应。默认开、可关——有人要助理，有人只要日记本。
3. **情绪洞察卡（月度）**："这个月你标记『疲惫』4 次，集中在项目冲刺周；『开心』6 次，5 次和家人有关。"附引用记录。
4. **照片时光回溯**："一年前的这周"卡片（纯数据 + 简短 AI 叙事）。

**数据依赖**：LifeLog → `LifeEntry`（ImagePath 单图 → Images 数组，Mood 结构化）。

### 5.5 任务中枢（Minds）

**功能描述**：Memo 升级为完整任务系统：子任务、截止、提醒（弹窗/邮件双通道沿用）、优先级、关联对象。

**AI 融入点**：
1. **自然语言建任务**：指令面板或捕获条直接说"周三上午九点提醒我给客户回电话"，AI 解析时间与动作（复用现有 Agent 时间解析能力）。
2. **大任务拆解**：任务详情"让助理拆解" → AI 生成子任务清单（diff 确认后写入）。
3. **智能排序**："今天先做什么"按钮 → AI 综合截止时间、优先级、近期记录关联度给出建议顺序及理由。
4. **到期摘要提醒**：通知内容 = 任务名 + AI 从关联记录提取的 1-2 句上下文（"关联你 8/19 记录的方案第 3 版反馈"）。
5. **周任务复盘**：回顾页展示完成率与拖延模式洞察。

**数据依赖**：Memo → `Task`（+Subtasks、SourceInboxId、AiContextSummary）。

### 5.6 回顾（Reflect）

**功能描述**：周报升级为"AI 与数据共创"文档，并扩展月度/年度回顾。

**共创三区布局**：
```
┌───────────────┬──────────────────────────┬─────────────┐
│ 事实区（只读）   │  叙事区（AI 初稿，可编辑）   │ 追问区        │
│ · 本周 23 条记录│  ## 本周工作                │（侧边对话）    │
│ · 完成 8 项任务 │  ### 重构项目                │ "把第二段      │
│ · 覆盖 3 个项目 │  ……（流式生成，每段标注      │  改正式一点"   │
│  [引用chips]   │   来源记录chips）           │ "补一下数据"   │
└───────────────┴──────────────────────────┴─────────────┘
```
- **事实区**：本周全部素材的结构化清单，每项可勾选纳入/排除——**用户通过控制事实来控制叙事**。
- **叙事区**：AI 初稿按现有周报 prompt 的强约束生成（只用本周事实、禁止虚构）；内联编辑，每段带来源引用；历史 Excel 参考机制保留。
- **追问区**：针对本周数据的任何提问；"生成另一个版本"。
- **进度外化**：周五下午自动就绪草稿（ProactiveJob），通知直达。

**数据依赖**：WeeklyReport → `ReflectDoc`（type: weekly/monthly/yearly、FactRefs、来源引用结构化）；WeeklyReportReference 保留为参考附件。

**OKR 文档（M2+，与周报同一共创范式）**：O/KR 结构化录入，或由周报素材 AI 起草；AI 自动从工作流记录中关联进展证据（哪条记录支撑了哪个 KR 的推进）；季度末一键生成复盘叙事。M1 仅在导航预留入口（空态占位）。

### 5.7 记忆库（Memory）★ 信任的基石

**功能描述**：AgentMemory 从后台搬到台前，成为一级页面。

- 分类视图：偏好 / 事实 / 背景 / 指令（沿用现有 category）。
- 每条记忆显示：来源（哪次对话/哪条记录提取）、重要度、最近使用时间。
- 用户可新增、编辑、删除、置顶；**删除即真删**（从 prompt 上下文移除）。
- 指令类记忆 = 用户自定义助理行为（"周报里不要用感叹号"），即原 ChatProject.Instructions 的去项目化版本。

**AI 融入点**：记忆提取沿用现有"LLM 语义提取 + 关键词回退"双通道；新增**记忆使用透明化**——侧边对话中可查看"本次回答用到了哪些记忆"。

### 5.8 全局指令面板（Command Bar）★ 唯一的"聊天"，但它是操作入口

**功能描述**：Ctrl+K 唤起，居中浮层。输入自然语言，AI 意图路由到：

| 意图类型 | 示例 | 执行方式 |
|---|---|---|
| **操作** | "把上周关于迁移的记录整理成一页" | 调用 Agent 工具链（搜索→汇总→export_file 成 DOCX） |
| **查询** | "我上次和老王聊排期是什么结论？" | 跨数据检索，答案带引用 chips |
| **创建** | "建个任务周五提醒我交材料" | 结构化创建，diff 确认 |
| **对话** | "帮我起草一封道歉邮件" | 纯生成，结果可一键存为记录/导出文件 |

**关键设计**：
- 面板内流式输出 + 工具调用进度（复用现有 SSE 事件流：token/tool_call/tool_result…）。
- 危险操作（shell、删除）强制确认（沿用现有 Confirm 机制）。
- 历史指令可回溯；**没有传统聊天列表页**，但指令历史可全文检索（承接原 ChatSession 数据）。
- Esc 即走，不打断心流。

### 5.9 上下文侧边对话（Context Panel）

**功能描述**：任何对象（记录/任务/周报/记忆/生活条目）右侧"💬 讨论"展开，对话自动携带该对象全文 + 关联上下文。

- 用途示例：对一条工作记录追问"这个方案的 risks？"；对周报追问"数据补一下"；对任务问"怎么推进第一步？"
- 对话中的有价值结论可一键【转为记录】或【存入记忆】。
- 每个对象的对话独立保存（attachToObjectId），也可在指令面板中检索。

### 5.10 主动助理（Proactive）

**功能描述**：ScheduledTask 升级为类型化的主动任务：

| 类型 | 触发 | 行为 |
|---|---|---|
| briefing 晨报 | 每日首次开机 / 固定时刻 | 生成今日流顶部晨报卡 + Toast 摘要 |
| weekly_draft 周报草稿 | 周五 16:00 | 周报初稿就绪并通知 |
| digest 提醒摘要 | 任务到期前 | 带上下文摘要的通知 |
| tidy 整理建议 | 每周日 | 收件箱清理/记录归档建议（≤3 条） |
| custom 自定义 | 自然语言设定 | 沿用现有 ScheduledTask 能力（AI 到点执行任务） |

**克制原则**：主动通知每天 ≤5 条，全部可在设置中逐类关闭。

### 5.11 内联 AI 与微交互（贯穿所有编辑场景）

- 选中文字 → 浮动条：【提炼 / 扩写 / 改写 / 翻译 / 追问】。
- 输入 `//` 触发 AI 续写 ghost text（Tab 采纳）。
- 任何 AI 生成块右上角固定三个动作：引用来源 / 重新生成 / 复制。

## 6. AI 交互规范（全局约束）

1. **溯源强制**：AI 关于用户数据的一切陈述附带来源引用（chips：来自哪条记录/任务/记忆）。无来源的个人数据陈述不允许出现。
2. **Diff 确认制**：AI 创建/修改用户数据 → 预览界面 + 确认；AI 自动落地的仅限其自身产出（摘要/标签/记忆），且标"AI 生成"角标。
3. **可撤销**：确认后的 AI 写操作进入撤销栈（Ctrl+Z 或通知内"撤销"）。
4. **流式优先**：所有生成 >1s 的场景必须流式（后端 SSE 已具备）。
5. **失败降级**：AI 不可用时，产品退化为完整的记录/任务工具——功能骨架不依赖 AI 存活。
6. **成本可见**：设置页显示本月 AI 调用量统计。

## 7. 数据模型：MiraiNote → Mirai 迁移映射

| MiraiNote 实体 | Mirai 实体 | 关键变化 |
|---|---|---|
| User | User | 不变（JWT 体系保留） |
| Memo | **Task** | +Subtask、+SourceInboxId、+AiContextSummary、Tags 结构化；RemindAt/RemindMethods/Priority 保留 |
| WorkLog | **WorkEntry** | +AiSummary、+AutoTags(JSON)、Category→ProjectId 外键、Tags→Tag 关联表；Content(Markdown) 保留 |
| LifeLog | **LifeEntry** | ImagePath→Images[]、Mood→结构化(标签+强度1-5)；Content(Markdown) 保留 |
| ChatSession/ChatMessage | **Conversation/Message** | +Type(command/context/briefing)、+AttachToObjectId；历史数据 Type=legacy，可检索 |
| ChatProject | （解散） | Instructions → 记忆库"指令"类条目；Project 分组 → 工作流分组 |
| WeeklyReport | **ReflectDoc** | +Type(weekly/monthly/yearly)、+FactRefs、来源引用结构化；IsEdited 保留 |
| WeeklyReportReference | ReflectReference | 保留（Excel 参考机制沿用） |
| AgentMemory | **MemoryItem** | 结构不变，前台化展示 + 使用透明化 |
| ScheduledTask | **ProactiveJob** | +JobType(briefing/weekly_draft/digest/tidy/custom) |
| —（新增） | **InboxItem** | Raw、AiParse(JSON)、Status(raw/triaged/dispatched/discarded)、DispatchTarget |
| —（新增） | **AIActionLog** | 每次 AI 写操作审计：意图、diff、用户决策（采纳/忽略/撤销）——质量度量与提示词迭代的数据基础 |
| —（新增，M3） | **NoteEmbedding** | Entry 向量化，支撑语义搜索与关联推荐 |

迁移原则：全量保留历史数据，一次性脚本迁移；聊天历史与记忆完整带入——**助理"记得"过去，是迁移的最大价值**。

## 8. 技术架构建议（可行性）

| 层 | 建议 | 理由 |
|---|---|---|
| 桌面壳 | **Tauri 2**（次选 Electron） | 团队前端为 Vue3+TS+Vite，可直接复用约 80% 界面代码；Tauri 体积小、原生支持托盘/全局快捷键/系统通知/自动更新 |
| 前端 | Vue3 + Pinia 复用改造 | 路由/信息架构按本文档重构；SSE 流式、Markdown 渲染、marked/dompurify 全部沿用 |
| 后端 | **V1 直连现有 ASP.NET Core API**（IIS 部署不动） | 40+ Agent 工具、SSE、认证、后台服务全部复用，MVP 成本最低 |
| 本地模式（V2/M3） | Kestrel 自托管于客户端进程 + EF Core 切 SQLite/LocalDB | "数据不出本机"卖点；SSE 与工具链零改动 |
| AI 服务 | DeepSeek（OpenAI 兼容）沿用；新增分拣/晨报等专用小 prompt | 现有 prompt 工程（周报强约束、记忆提取双通道）直接复用 |
| 检索 | V1 沿用关键词+SQL；M3 引入 embedding + 向量检索 | 现库无 RAG，不阻塞 MVP |

**新增后端服务**：InboxTriageService（分拣）、BriefingService（晨报）、AIActionAudit（写操作审计中间层）。工具层新增：`dispatch_inbox`、`query_day_overview`（部分已有雏形）。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| AI 分拣错误伤害信任 | 置信度阈值 + "我不确定"显式表达 + 一句话重分拣；所有分拣可撤销 |
| 主动通知变成骚扰 | 每日上限 + 逐类开关 + 通知内"不再提示" |
| 摘要/晨报编造事实 | 强约束 prompt 体系（沿用周报经验）+ 溯源 chips 强制 + 事实区人工可控 |
| 桌面壳全局热键与游戏/其他软件冲突 | 热键可配置，冲突时降级为托盘菜单捕获 |
| 双形态（连接服务器 vs 本地模式）数据一致性 | V1 只做连接模式；本地模式独立里程碑，同步方案届时单独评审 |
| AI 不可用 | 第 6.5 条降级原则：功能骨架不依赖 AI |
